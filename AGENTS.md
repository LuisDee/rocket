# Agent operating rules

The block above is generated by Next and rewritten on every `next dev`. Everything
below is ours; `next` does not touch it. Do not delete the delimiters.

Read [REDLINES.md](REDLINES.md) before touching anything.

## 1. Source of truth

`docs/specs/` is authoritative -- eight files, ~250 lines, read them. Every other
document, this one included, is an extract. **If an extract disagrees with the
specs, the specs win: fix the extract, do not argue from it.**

The one exception, and it is the project's own standing rule: specs describe
intent, the database and the code describe reality. Where a spec asserts
something the schema contradicts, stop and report -- do not write a migration to
make an aspirational spec value true.

Known spec defects, open at seeding (2026-08-15), each carrying a decision-log
entry: the seed block's week 2 ramp violates the ramp cap the planner must
enforce; the readiness score does not define how the musculoskeletal component
enters it.

## 2. Housekeeping owed, not yet paid

[docs/decisions.md](docs/decisions.md) and [docs/ci-gates.md](docs/ci-gates.md)
are skeletal on purpose -- created now so their absence cannot go unnoticed,
filled in as real decisions and gates land.

Landing code or a decision without the matching entry is a bug, not a clean
state. **Do not backfill in bulk after the fact** -- add the entry in the same
commit as the thing it documents. A log written retrospectively records what
someone remembered, not what happened.

Use `PROVISIONAL` heavily. Every training threshold in `config/training.ts` was
chosen before there was data to choose it from, and each one should say so along
with what would settle it.

## 3. Tasks before nontrivial code

Any change that is not a typo or a doc edit gets a `tasks/<slug>.md` file first
-- see [tasks/README.md](tasks/README.md). The header is the mini-spec: write it,
then **stop and wait for human review** before starting the checklist.

This matters more here, not less. Solo work under deadline is exactly the
condition in which an agent writes 400 confident lines in the wrong direction.
Five minutes reading a frozen header is the cheapest gate in the repo.

Every commit carries a `Task: tasks/<slug>.md` trailer and is appended to that
file's `## Commits` section before push. Mechanically enforced by
`scripts/check_task_trace.py` on pre-push, fails closed.

Stage with explicit paths, never `git add -A`, whenever another agent may be
working the same worktree -- the gate sees a correct trailer on a commit whose
diff belongs to someone else and passes it. (Discovered 2026-09-06: two agents
committed each other's staged files.)

## 4. Prove the gate fails

When you add a gate, **break something on purpose, watch it catch, revert.**
Record what you broke in the `docs/ci-gates.md` row. A gate nobody watched fail
is a decoration, and a gate that cannot fail is worse than none -- it stops
anyone looking.

Corollary, applied periodically: try to _satisfy the gate without doing the work_.
If a coverage gate is satisfied by a bare import, it is measuring imports.

## 5. Record negative results

If you evaluate a tool, rule, or approach and reject it, write down that you did
and why. A config option that turns out not to exist gets removed **and noted**,
not silently dropped -- otherwise the next person re-derives the same dead end.

## 6. When a rule here was born from an incident, say so

Append `(Discovered YYYY-MM-DD: <what happened>)` to the rule. Rules with their
originating incident attached survive; rules without one get deleted by the next
person who finds them annoying.

## 8. Scope discipline

Every feature must function on cached data and manual check-ins alone
(`docs/specs/00-overview.md`, invariant 2). Garmin, DoHardThings, and routr are
all upgrades to a system that already works without them. If an integration
outage would break a code path, that code path is wrong.
